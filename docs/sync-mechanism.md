# 画布与 XMind 同步机制

## 数据路径

1. 编辑操作先更新客户端模型，再进入 `WhiteboardSyncQueue`。队列按顺序发送操作，并用稳定的 `opId` 处理断线重发。
2. `WhiteboardStorage` 把未确认操作写入 IndexedDB 的 outbox，并以 localStorage 作为小容量兜底；画布快照另存于 snapshots。重新打开画布时先恢复本地数据，再连接 WebSocket。
3. 服务端在画布队列中校验操作、版本和权限，使用数据库事务提交状态与操作回执，随后向所有连接广播规范化操作。客户端收到确认后删除 outbox 中对应操作；版本冲突则拉取权威快照并重放未确认操作。
4. 保存请求在操作队列清空后提交。页面短时离线时操作留在本机；服务端写入成功、客户端未收到确认时，重连后仍用原 `opId` 重发，服务端按回执去重。

## 短时画布锁

服务端以连接为单位维护 3.5 秒编辑租约。画布指针操作、内容输入和实际写入都会续租；其他连接收到 `board-lock` 后进入只读状态。服务端也会拒绝竞争写入并返回可重试的 `BOARD_BUSY`，因此锁定不依赖客户端界面是否正常运行。持续拖动时租约广播合并到约每秒一次，避免按每个操作向全部成员发送重复锁消息。

编辑端在未确认操作仍排队时低频续租；正常情况下，停止编辑约 3.5 秒且操作已提交后主动释放。服务端等待正在处理的画布操作完成，广播解锁时附带已提交版本。接收端只有应用到该版本后才恢复编辑；若消息缺失或版本落后，会保持只读并重同步。分片快照校验期间到达的实时操作暂存，快照应用后按顺序重放，避免旧快照覆盖新操作。

断线、切换画布和超时仍会释放服务端租约，避免永久占用。暂时性同步失败会自动重试；若停止编辑 30 秒后仍无法提交，停止为草稿无限续租，但未提交内容继续留在本地队列中，界面仍显示同步中或待同步，不能视为已同步。不可恢复的校验错误才显示同步问题入口。断网时无法保证尚未上传的草稿立即出现在别人设备上。工作表格的细粒度单元格锁仍用于版本保护。

## XMind 双向同步

只有连接的脑图内容与关系会同步到 XMind；其他画布元素通过画布服务端与 WebSocket 在成员间同步。画布脑图修改先作为普通画布操作提交，再自动调用 XMind 增量同步。服务端先检查远端哈希，应用结构化补丁，回读验证，最后推进同步基线。XMind 写入期间出现新的画布修改时，新修改留在待处理状态，由下一轮增量继续处理。

页面可见且连接有效时定期检查 XMind 远端变化，返回页面时强制检查。只有远端修改时自动载入，同时保留本地专属字段；两端同时改动时停止自动覆盖，并保留人工冲突处理入口。XMind 授权失效、远端拒绝或回读不一致时，画布内容仍留在本地和本站服务端，不会被静默丢弃。

## 故障恢复

- 登录画布的草稿按账号和画布隔离。IndexedDB v6 使用独立 outboxJournal，在同一读写事务内合并多标签页记录；localStorage 兜底按标签页写入。已确认、被合并的操作以删除标记保留，防止旧标签页或旧版 outbox 将它们复活。旧 outbox 只迁移读取，不覆盖新日志。
- 草稿读取失败或格式损坏时禁止编辑、禁止覆盖原存储，并自动重试；恢复完毕才允许加入同步。草稿写入失败时暂停编辑，每 5 秒重试；存储恢复后自动解锁。写入结果按画布、账号代次和编辑序号检查，旧写入完成不能把新输入误标为已保存。页面离开时仍有未落盘修改会触发浏览器离开提示。
- 登录/共享权限失效、数据版本不兼容，以及无法隔离的持久同步错误暂停编辑。明确识别的失败图片保留并隔离，不锁住能独立提交的便签、文字、背景。普通离线在本地草稿可保存时允许编辑，回到页面、网络恢复后自动补同步。
- 从服务器接收快照或提交前先收集尚未入队的文字输入，再重放草稿。连续的未发送便签/文字快照可合并，但每次替换使用新操作 ID；发送过的 ID 和内容不再变更。收到自己的提交确认后，只调整后续未发送操作所依赖的内容版本，真实的其他版本冲突仍由服务端拒绝；样式修改不能降低内容版本号。

- 本地草稿恢复与网络提交分开：队列中的错误仅暂停提交，不截断后续背景、文字等可重放草稿。离线启动、服务器快照及其他成员的提交之后均重新应用待提交修改；本地显示恢复不代表云端已保存。目标图层锁定时仍保留队列，且不覆盖锁定内容。
- 本地存储必须明确返回成功才算保存；存储接口缺失也视为失败，不能据此放行画布切换或标记缓存已保存。
- 服务端明确指出图片权限失败后，队列保留原操作，并允许其后没有依赖关系的文字、便签和背景设置继续提交。失败批次不会拆分；同一对象、同一设置以及图层/画框/表格等无法证明独立的操作保留顺序。确认和重试按操作 ID 定位，不能误删除队首失败草稿。图片本身只在用户手动重试时再次提交。

- 背景类型校验与前端选项一致；由旧版校验造成的 `Background type is unsupported.` 阻塞草稿会在恢复时重新排队。
- WebSocket 操作 15 秒没有确认时重新连接；快照重同步 30 秒无响应时重新连接。原操作 ID 保证重发可去重。
- `BOARD_BUSY`、限流和暂时性服务错误自动重试；不可恢复的校验错误保留本地操作并显示同步问题入口。
- 单元格临时占用使用 `SHEET_CELL_BUSY` 自动退避重试，旧服务端的同义提示也兼容；真正的单元格版本冲突仍保留草稿等待处理。暂时性错误和画布版本重同步不会提前结束单元格提交等待，也不反复弹出错误提示。
- 重同步快照不会清除尚未到期的重试退避；重复调度不缩短等待，收到提交确认后才重置退避。发送异常会自动重试，重同步请求发送失败会重连，切换画布后旧重试回调不提交新画布操作。本地重放因目标图层锁定暂停后，在收到解锁状态并通过重放检查时自动继续。
- 图片权限拒绝会暂停队列，保留失败操作及后续草稿，并立即释放编辑锁；暂停期间继续本地编辑不会续锁，也不会自动反复提交失败图片。权限检查允许使用自己的笔记图片和当前可读的共享笔记页面图片；未共享页面和已撤销的来源权限仍会拒绝，提示包含图片名称或元素 ID。旧版通用图片权限报错在恢复本地队列时尝试一次新版校验，若仍失败则保持暂停。
- 图片授权确实无法恢复时，“同步问题”中的“重新选择原图”会上传用户选定的图片，替换队列里同一失效图片的所有引用，保留其他操作及图片的位置、尺寸等修改。改过内容的操作使用新操作 ID，并先保存本地队列再继续同步；上传、本地保存失败或切换账号/画布时不会自动丢弃草稿。
- 离线或服务端不可用时保留 outbox，恢复连接后按顺序提交。IndexedDB 与 localStorage 都不可用或容量不足时，界面会提示导出副本。
