# 网页版本更新提示

网页使用服务端注入的 `data-static-build` 识别当前发布。指纹涵盖静态资源、HTML 和参与 HTML 输出的壁纸配置；内容没有变化时，重启不会生成新指纹。

前端初始化后请求 `/api/app-version`，前台每 60～75 秒检查一次（随机延迟分散请求）；切回前台、页面恢复、网络恢复和 WebSocket 连接成功时也检查，10 秒内的检查合并。后台、离线或页面被挂起时取消请求并清除定时器，恢复后继续检查。网络错误、非成功响应和无效版本值只触发失败退避，不显示更新提示；失败间隔逐步增长，最长 15 分钟，恢复事件不会绕过退避。仅版本接口 `/api/app-version` 的请求和响应在本功能中明确禁止缓存，兼容现有 API 加密传输；其他接口保持各自原有缓存策略。

服务端将资源目录检查结果缓存 5 秒，并合并并发扫描；每次请求只额外检查项目根目录的发布状态，发布完成后立即使扫描缓存失效。HTML 使用计算该指纹时采集的内容，避免入口与指纹来自不同时间。构建期间或扫描期间发生发布切换时返回带 `Retry-After` 的 503，不生成过渡指纹。没有内容变化的构建仍保持原指纹。

`npm run build` 使用一个发布事务覆盖 vendor 和 frontend 两个阶段，单独运行 frontend、vendor、backgrounds 的写入也受同一发布锁保护。后台缩略图先在内存生成完整结果再发布。`.static-publication.lock/` 和 `.static-publication.json` 位于 `public` 外，不提供下载，也不包含旧版资源。写入失败会留下失败状态，成功重新构建后恢复；构建进程被强制终止时保留锁并拒绝继续发布，需确认构建进程已退出后清理锁目录再重建。部署应在目标目录完整执行构建，避免绕过锁向正在运行的 `public` 逐个复制文件。

发现版本不同时立即停止版本检查，清除定时器并移除恢复事件监听。这个停止状态持续到页面刷新：即使弹窗一直无人处理，或用户选择“稍后自行刷新”，也不会再次轮询或因重连而检查。右下角提示显示“网页已有新版本，请刷新”，文字下方提供“刷新网页”按钮；Esc 等同于稍后处理。右下角提示优先挂载，弹窗成功打开后隐藏，关闭弹窗后恢复显示，避免两个提示同时出现。弹窗展示失败时仍保留右下角刷新入口；界面异常单独记录，不当作网络错误吞掉。

检测到更新后，若用户仍在绘画、拖拽、中文输入法组合输入，或焦点仍位于文字编辑器中，先只显示角落提示。通过操作结束、焦点变化、已有弹窗关闭等事件，在可打断时弹出更新提示；不轮询空闲状态。选择稍后会恢复弹窗前的焦点及可恢复的文本选区。用户直接点击角落刷新按钮后，取消尚未显示的弹窗，避免保存过程中突然弹出。

点击刷新前，检查是否有快传文件正在传输，短暂禁止其他区域输入和操作，并调用笔记、规划和画布的安全保存流程。画布流程包含输入提交、工作表草稿、访客快照或账号待同步操作的本地持久化。每个保存阶段后复核账号、画布和编辑上下文，最终复核笔记编辑序号及规划草稿；有变化则留在页面。保存失败时恢复编辑，不强制刷新。未同步操作通过已有草稿恢复机制继续同步。

等待保存最多 15 秒，期间随时可以选择稍后或按 Esc；超时、取消后立即恢复编辑，迟到的保存结果不能触发刷新。IndexedDB 写入无法可靠地强制取消，因此仍跟踪原保存 Promise，在它结束前保持刷新按钮禁用以避免重复写入；稍后按钮始终可用。保存结束后可重试。笔记 IndexedDB 回调中的同步写入异常也会正确中止事务并返回具体原因。

从右下角发起刷新时，准备期间显示“取消刷新”，键盘焦点移到取消入口，Esc 同样可以取消。进度区分检查连接、保存内容和确认网页可用；失败信息标明笔记、规划或画布，存储配额不足会给出释放空间的建议。刷新复用画布保存逻辑时使用独立的刷新错误文案，不再提示“切换画布”。

仅在用户点击刷新后，保存前和保存后各对当前页面入口发送一次禁止缓存的 HEAD 请求，超时为 5 秒，不跟随跳转；响应必须成功且为 HTML。离线、连接失败、发布中（503）或入口异常都保留当前页面，恢复可操作状态并提示重试。最终再次验证保存序号，防止等待入口检查时出现新的未保存内容。这两次入口检查不获取版本信息，也不会恢复版本轮询；无法完全排除检查成功后网络再次中断的时间窗口。

不保留旧版静态资源，也不自动倒计时刷新。回滚导致指纹不同，同样提示更新。本功能首次部署前已经打开的页面没有检测代码，需要先刷新一次才能启用。
