# 画布群聊桌面通知

采用标准 Web Push、VAPID 和通知专用 Service Worker，不引入 Firebase SDK 或额外托管业务服务。用户关闭画布网页后，只要浏览器仍在运行且推送服务可达，就能接收 Windows 系统通知。

## 配置与开启

1. 安装依赖 `npm ci`，准备 `.env`，生产环境设置正确的 HTTPS `PUBLIC_BASE_URL`。
2. 运行 `npm run setup:push -- mailto:admin@example.com`。也可省略联系人参数，使用 `.env` 中配置的正式 HTTPS 域名。脚本生成公私钥并启用通知，已有密钥时拒绝覆盖。密钥应单独安全备份；不要提交 `.env`。
3. 重启服务。每个浏览器登录后，在“聊天 → 筛选与提醒 → 开启桌面通知”中授权。网站无法代替用户授予浏览器通知权限。
4. “消息提醒”的全部、仅提及、关闭设置同时作用于推送；“关闭此浏览器桌面通知”只取消当前浏览器订阅。

本机 localhost 可开发测试，普通 HTTP IP 地址不支持。反向代理部署 `/board/` 等子路径时，须将该路径下的 `push-sw.js` 正确转发为 JavaScript，不能返回登录页或 HTML。脚本以页面目录注册作用域，不应强制长期缓存。Service Worker 不拦截请求，不缓存画布或聊天 API。

## 投递与隐私

- 同一接收用户、同一画布，每十分钟最多选择一条消息推送。窗口从推送服务首次接受消息时开始，限频记录存入 SQLite，重启不清零。窗口内的新消息不入队、不在到期后补发；窗口结束后的新消息可再次触发。同一条消息可投递到该用户已订阅的各设备，每个设备收到一次；不同画布独立计时。暂时失败的发送保留原有重试逻辑。

- 订阅绑定当前登录会话。会话撤销、退出登录或删除账号会级联删除订阅与待发送任务；过期会话不再发送。重新登录后可再次点击开启通知。
- 消息和待发送任务在同一 SQLite 事务中提交，重复发送同一消息不会重复入队。发送者本人和无权访问画布的人不接收。
- 发送前再次检查画布权限、历史可见范围、个人删除、撤回、提醒偏好和已读位置。延迟约两秒给前台已读同步留出时间；多个设备同时处理时仍可能收到已读消息的通知。
- 发送批次上限 20；暂时失败指数退避，最多五次；任务一小时过期。推送服务保留消息五分钟，404/410 自动删除失效订阅。订阅端点只接受已知浏览器厂商的 HTTPS 主机，阻止任意地址请求。
- 锁屏通知不包含用户名、画布名称或消息原文。每块画布使用同一通知标签，点击复用现有窗口或打开画布中的消息。平台确认接收并不等于设备已显示；网络中断后的重试也无法承诺严格一次投递。
- 已交给推送服务的通知无法在退出登录后撤回，因此采用通用提示；点击后仍须通过正常登录与画布访问检查。
- 通知点击使用干净的应用地址，不添加画布或消息查询参数。Service Worker 通过消息通道交付位置；窗口尚未就绪时，定位信息按窗口暂存在 IndexedDB，页面确认接收后删除，一小时失效。不解析或兼容旧通知的 URL 定位字段。
- 服务器关闭推送开关后，已有订阅仍可在页面取消。订阅状态刷新不会覆盖正在进行的按钮操作；已订阅浏览器访问页面时会检查通知脚本更新。

Chrome 使用 Google 的推送基础设施。服务器和用户网络均需能访问相关推送服务；在限制 Google 服务的网络中不能保证送达。关闭所有浏览器进程、系统免打扰或禁用通知时，也不能保证实时弹窗。
